# CHANGELOG Directory

This directory contains chronological records of work sessions and progress on the agent_tools project.

## Purpose

- Track progress between context length compactions
- Document key decisions and design choices
- Maintain continuity across multiple work sessions
- Serve as memory for Claude between sessions

## File Naming Convention

Files are named with the format: `YYYY-MM-DD-description.md`

For example:
- `2025-03-24-fetch_docs_integration.md`

## Content Structure

Each changelog entry should include:

1. **Current Status**: Overall state of the project/module
2. **Components Created/Modified**: List of files and changes made
3. **Key Design Decisions**: Important architectural choices
4. **Next Steps**: Planned future work
5. **Current Limitations**: Known issues or constraints
6. **Resolved Issues**: Problems that were fixed

## Usage

At the beginning of a session, Claude should review the most recent changelog entries to understand the current state of the project. At the end of a significant work session, Claude should create a new changelog entry to document progress.

## Important Notes

- Changelogs should be concise but informative
- Focus on decisions and rationales, not just listing changes
- Include any critical issues that need to be addressed in future sessions
